# 実行評価（2026-10-30）

Claude Code 2.1.314 / `claude-fable-5-1`。通常指示、旧スキル、改訂版を別プロセスで評価した。単発の合成課題であり、一般的な性能向上率は算出しない。

## 確認できた成果

- 決済の再試行バグは3条件すべてで修正できた。評価者が保持した5件の契約テストは元のバグ実装で3件失敗、すべての生成修正版で5件合格した。通常指示でも正しく修正でき、このケースで正しさの上積みは示していない。
- 改訂版の生成テストには「サーバー確定後に応答を失っても決済は1件」という業務結果の再現が追加された。通常指示・旧版では主にキーの同一性を検査していた。
- 文案で調査に着手していないのに「現在確認中」と書く誤りは、改訂1では解消したが改訂2で再発した。全利用者への観測範囲の拡張も残った。**一度読むだけで誤断定が安定して防げるとは実証できなかった。**
- 新しい二文メール課題は通常指示も改訂版も事実を保った。改訂版は前置きと解説が増えた。追加の価値がない場面もある。

## 二段階の照合

生成済み回答と原資料を、別の新規Claudeプロセスへ `claim-audit.md` とともに渡した。既存の失敗回答と新しい架空の誤った文案の2件で、確認中・全員確認済み・原因判明・明日必ず復旧という主要な根拠のない主張を除去できた。修正前後と入力全文は `two-stage-audit.json` / `prompts/` に保存した。

追加時間は36.08秒と24.62秒。この評価は二段階運用であり、一回の生成と同条件ではない。スキルなしの二段目レビュー対照は実行していないため、改善を専用手順だけの効果とは断定できない。ログ不在の解釈など、修正後にも見落としは残る。

## 再現方法と限界

`results.json` は合成課題、採点基準、出力、モデル、入力SHA-256、所要時間を含む。`prompts/` に実際の入力を保存。新規プロセスにUTF-8で標準入力し、`claude -p --safe-mode --tools '' --disable-slash-commands --no-session-persistence --output-format json` を用いた。応答中のPythonは目視確認後、生成テストと `test_contract.py` をpytestで実行した。`execution-results.json` は実行件数を記録する。

旧版基準は commit `882dfba8b7df1c609c5b3232959495f4f41614d3`。元の4ケースの失敗は改訂担当へ共有したので、改訂時の同じケースは開発用回帰評価であり独立した最終評価ではない。新しい二文文案・二段目文案は改訂後に追加した。全条件で答えの基準は生成側へ渡していない。評価者は条件を知っており盲検ではない。

比較時はスキル本体と検証ケース以外の参照文書をまとめて入力した。通常運用の必要時読み込みより多い入力で、コード課題の入力文字数は通常707、旧版8,359、改訂1は8,249。二文文案は通常173、改訂7,715文字だった。異なるモデル、実案件、長期作業への再現性、統計的な優位性は未検証。コスト欄、セッションID、ローカル絶対パスは公開データに含めていない。
