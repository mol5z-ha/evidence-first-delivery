# Claudeによる実行付き比較

2026-10-30、1つの合成Python案件を2条件で1回ずつ実行。モデルは両方 `claude-opus-5-5`。通常の修正依頼と、同じ依頼に改訂スキル本文・診断/受入確認資料を追加した場合を比較した。

## 方法

- `baseline/` と `revised/` に同一の実装・仕様・既存テストを配置した。
- 課題は、カーソル付き全件エクスポートの後半欠落を調査・修正・検証すること。原因や望ましいパッチを依頼文に含めていない。READMEにはAPIの契約を提示した。
- 新しいClaudeプロセスを `--safe-mode --restricted --disable-slash-commands --no-session-persistence` で起動し、Read/Write/Edit/Bashのみ許可した。操作対象をそれぞれの作業ディレクトリ内に限定し、ネットワークやインストールは禁止した。
- 採点用の9契約ケースはClaudeの作業ディレクトリ外の `grade_live.py` に保存し、プロンプトへ含めなかった。取得結果、順序・重複、カーソル、要求回数、例外伝播を実行検査した。
- ストリームJSONでツール呼出しと実際の結果を保存した。モデルの最終報告だけで実行を認定していない。

## 観測結果

| 条件 | モデルが追加した試験の変更前 | 同じ試験の変更後 | 外部契約試験 | 経過時間 |
| --- | --- | --- | --- | --- |
| スキルなし | 9件中2件失敗 | 9件成功 | 9/9成功 | 26.16秒 |
| 改訂スキルあり | 8件中5件失敗 | 8件成功 | 9/9成功 | 25.37秒 |

両条件とも、試験追加→変更前失敗→実装修正→変更後成功を実行した。スキルなしはループを同等の構造へ組み替え、改訂版はループ条件1行を変更した。どちらも仕様を満たす修正だった。

この案件では、成功率・工程実行にスキルの優位性は観測されなかった。1回の経過時間差は性能改善の根拠にならない。改訂版で失敗した試験が多いのは追加したケースの選び方が違うためで、点数の優位として扱わない。

## 証拠と追試

- `fixture/`：実行前の仕様、実装、既存テスト。
- `baseline/` と `revised/`：Claudeが実際に作成したファイルと初期状態との差分。
- `*-prompt.txt`：入力。ローカルの絶対パスは `<trial-root>`、Python実行ファイルは `<python>` に置換した。
- `*-trace.json`：実際のツール呼出しと応答。モデルの自己申告だけでなく、変更前失敗・変更後成功の出力を含む。セッション情報は除外した。
- `results.json`：9契約の結果、モデル、経過時間、入力とスキルスナップショットのSHA-256。
- `skill-snapshot/`：実行時に渡したスキル本文と参照資料。後の最終版には主張の裏付け・予定表現に関する小さな文言調整があり、この試験はこのスナップショットの評価である。

Python 3の標準ライブラリだけで次を実行できる。

```sh
python test_external_contract.py
python -m unittest discover -s baseline -v
python -m unittest discover -s revised -v
```

外部契約試験は合成fixtureと生成コードを実行する。初期版は6/9、両修正版は9/9となる。Claude評価を再実行する場合はfixtureを新しい各作業ディレクトリへコピーし、プレースホルダーを環境に合わせて置換する。採点ファイルと他条件の出力は評価対象へ渡さない。

## 限界

小さく仕様が明確な1課題を各1回実行した結果であり、複雑な実案件や長時間作業への一般化はできない。APIはスタブのみ。採点ファイルへのアクセスはログに観測されなかったが、BashにはOSレベルのファイル隔離を設けていない。今回の実行付き試験のモデルは `claude-opus-5-5` で、別途のテキスト比較の `claude-fable-5-1` と異なるため成績を合算しない。単発の約0.8秒差を速度向上と扱わない。
